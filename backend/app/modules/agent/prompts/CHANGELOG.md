# Prompt changelog

Every change to a file in this folder gets a line here: the prompt `id@version`, what changed,
and the eval score of the run that accompanied it (`CONTRIBUTING.md`: prompt changes need an
eval result).

| Prompt | Change | Eval |
|---|---|---|
| all `v1.*` | Moved out of Python into files, text unchanged (phase 2, task 2.1) | n/a: no behaviour change |
| `base`, `context`, `playbook.*`, `tool.*`, `engine.*`, `history.*`, `classifier.*`, `memory.*`, `vision.*`, `inbound.*`, `gateway.*` | First versions for the v2 agent (phase 2, tasks 2.4-2.15) | Not yet run: needs the live evals (`evals/run.py`) |
| templates `holding`, `quote_card*`, `payment_*`, `handed_off`, `too_long`, `rate_limited` | First versions, en / ta / ta-en / hi / hi-en | Tamil and Hindi texts need a native speaker's review |
| `playbook.custom_or_future_order@2` | Ask the owner in the same turn as promising to check (live eval: the model promised without asking) | Live evals 29 Oct: 0.95 before |
| `context@3`, `playbook.new_order@2`, `playbook.custom_or_future_order@3`, `quote_card@2` | Pre-orders: "Coming up" items with per-day stock, a `date` on the draft, the day on the quote card | To run |
| `base@2` | Item ids are for tool calls only; the reply uses the item's name (live run 7 Nov: the model wrote "Today we have ie19dca, i4d09c3"). The output check now rejects ids in replies | Unit-tested; live evals to re-run |
| `playbook.owner_answer@1` | New: a turn triggered by the owner's answer passes that answer on, instead of re-answering the customer's last message (live run 7 Nov: the agent repeated the menu after "i got the payment directly"). The output check also rejects a shop-event reply that repeats the last one | Unit-tested; live evals to re-run |
| template `owner_answer_relay@1` | New: if the assistant can't write a reply to the owner's answer, the customer gets the owner's own words ("Update from the shop: ..."), not the generic holding message | Unit-tested (model outage, repeating replies); Tamil and Hindi need a native speaker's review |
| output check (code) | A diet word (eggless, allergen ...) is allowed in a reply that hands the question to the shop after ask_shop_owner ran; "I've asked the shop" now counts as a promise to check (live eval 7 Nov: the right steps, but the reply was rejected for the word eggless and the turn fell back) | Live evals re-run |
| `base@3`, `playbook.small_talk@2`, `playbook.product_question@2`, `playbook.custom_or_future_order@4` | Voice: talks like a person on the shop's team (no self-introduction, no "sir/madam"), still honest if a customer sincerely asks whether they are talking to a person or a bot. Written for any kind of online shop (clothes, jewellery, beauty, plants, food), not only food: facts about material, size, fit and care, returns and warranty go to the owner when the shop hasn't listed them | Live evals: `any_shop.jsonl` |
| output check (code) | Rejects "I am X's assistant", "as an AI", "sir/madam", "kindly" unless the customer asked what they are talking to | Unit-tested |
| `base@3` (voice) | The assistant no longer calls customers sir, madam or ma'am, and doesn't guess gender or use gendered terms (anna, akka, bhaiya, didi) unless the customer did first (live check 7 Nov: "Hii madam" to a customer who never said who they were). The output check rejects them | Unit-tested; live evals re-run |
| `playbook.owner_answer@2` | Treat the owner's answer as complete; a turn passing it on can no longer call ask_shop_owner (code), because the model invented a follow-up question (sizes, prices) and never told the customer (live eval 7 Nov) | Live evals re-run |
| `playbook.small_talk@3`, new `playbook.menu@1`, `playbook.new_order@3`, `playbook.custom_or_future_order@5`, `context@4`, `tool.ask_shop_owner@2` | A greeting no longer lists products (live chat 7 Nov: "We have Brownie, Chocolate cookie ..." to a plain "HII"). "What do you have?" gets today's items (at most six, then a narrowing question or the menu photo) and the pre-orders with day, price and last order day. Items under Coming up are open for pre-order: the agent says yes and takes the order, and no longer asks the owner whether they are open (the cake was listed with 20 left and the owner was still asked). ask_shop_owner takes a `confidence` (0-100): 75 or more is sent back once, and a question about a listed pre-order that asks for nothing beyond the listing is sent back by code | Live evals: `preorders_and_menu.jsonl` |
| `playbook.menu@2` (wording), `playbook.new_order@4` (wording); output check (code) | The last day to order is mentioned only when one is listed (live chat 7 Nov: "Last day to order isn't mentioned here"). A menu answer must include the open pre-orders: the model is asked once to add them, and the reply is sent as written after that (live chat: "what do you have?" left the Diwali cake out). Tone slips ("I am ...'s assistant", "madam") the model won't fix are cleaned up in code instead of becoming the holding message | Unit-tested; live evals re-run |
| model gateway (code) | The circuit breaker counts a call once after its retries, only for failures of the model service, and stays open 30 seconds (was: every attempt, content-filter 400s included, 2 minutes). Live eval 7 Nov: a brief network blip plus three flagged test messages switched the assistant off for 65 turns; flagged messages could have done the same to a real shop | Unit-tested |
