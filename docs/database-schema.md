# sellix database schema (v2 design)

> **Status: design for review. Nothing is migrated yet.** Once approved, it's implemented as new migrations in small steps (section 7).

## 1. Design decisions

| # | Decision | Why |
|---|---|---|
| 1 | **Postgres**, relational core plus **JSONB** for what varies by category | Orders, payments, stock holds and reporting need transactions and SQL; product details differ per category and fit JSONB (indexable, queryable) |
| 2 | **Every shop-owned table has `merchant_id`, and its primary key is `(merchant_id, id)`**; foreign keys between shop tables include `merchant_id` | The database itself enforces that one shop's rows can never point at another shop's rows. It's also the exact layout Citus needs to split shops across servers later, with no key migration. |
| 3 | **Every product has at least one variant**; stock, prices and order lines always point at a variant | One code path for "plain brownie" and "kurti, M, red". A product without options gets one default variant. |
| 4 | **Options split two ways:** stock options (Size, Colour) create variants; order-time choices (phone model, cake message, gift wrap) don't | Avoids pre-creating thousands of combinations nobody stocks |
| 5 | **Five stock modes per product:** `daily`, `inventory`, `made_to_order`, `unlimited`, plus per-unit tracking for serial numbers | Bakery, clothing, custom gifts, print-on-demand and phone resellers all work the same way underneath |
| 6 | **Every reservation of something limited is one conditional UPDATE** (stock, capacity slots, serial units) | Two customers can never get the last item or the last slot, at any scale |
| 7 | **Money in integer minor units** (paise, cents) with a currency code; **quantities as `numeric(12,3)`** | Exact money; quantities can be 2.5 metres of fabric or 0.75 kg of sweets |
| 8 | **Orders keep snapshots** (names, option labels, prices, address) | Editing or deleting a product never changes past orders or invoices |
| 9 | **Order status split into three:** lifecycle, payment and fulfilment | Advance payments, partial refunds, partial shipments and returns don't fight over one status field |
| 10 | **High-volume history tables are partitioned by month:** messages, stock movements, order events, AI usage, webhook events, audit log, notifications | Fast queries, cheap retention (drop a month instead of deleting rows), DPDP data limits |
| 11 | **Images and files live in object storage** (Firebase Storage or S3); the database stores keys and metadata | Database stays small and fast |
| 12 | **Search lives in Postgres:** full-text (`tsvector`), fuzzy (`pg_trgm`) and meaning/photo similarity (`pgvector`) | The agent can search a 5,000-item catalog without a second database |
| 13 | **Row-level security on every table**, no policies | The backend connects as owner; nothing is readable through any public API layer |
| 14 | Platform tables (users, sessions, category templates, plans, the webhook inbox) are **global**, not per shop | A user can manage several shops; templates are shared |

**Naming:** tables in plural snake_case; `id uuid` generated by the database; `created_at` / `updated_at timestamptz` (UTC) with the existing `set_updated_at()` trigger; status columns are `text` with `check` constraints (not Postgres enums, so adding a value is a one-line migration).

## 2. The product model in one picture

```
category_templates (global: "clothing", "bakery", "jewellery", ...)
        │ suggests options, attributes, stock mode, questions
        ▼
products ─── product_options ─── product_option_values
   │            (Size, Colour = stock options   →  create variants)
   │            (Phone model, Gift wrap = order-time choices → priced add-ons)
   │
   ├── product_variants (the sellable unit: "Kurti / M / Red", price, SKU)
   │       ├── stock_levels      (daily or running stock, held, available)
   │       ├── inventory_units   (per-unit serial numbers, optional)
   │       ├── variant_price_tiers (100+ pieces at a lower price)
   │       └── bundle_components (a hamper made of other variants)
   ├── personalization_fields (cake message, name to engrave, photo to print)
   ├── capacity_slots        (made to order: N per day or per time slot)
   ├── product_media → media_assets (object storage)
   ├── product_aliases       ("choco cookie" = Scoop cookie / Chocolate)
   └── product_search        (text, fuzzy and vector search for the agent)
```

## 3. Tables

Legend: 🟢 exists today (kept, possibly extended) · 🆕 new · 🔁 replaces an existing table.

### 3.1 Shops

```sql
-- 🟢 extended
create table merchants (
  id uuid primary key default gen_random_uuid(),
  name text not null,
  handle text unique,                        -- short public handle (web store, links)
  business_category text,                    -- category_templates.code chosen at onboarding
  country char(2) not null default 'IN',
  currency char(3) not null default 'INR',   -- the shop's main currency
  timezone text not null default 'Asia/Kolkata',
  gstin text,                                -- for GST invoices, if registered
  agent_enabled boolean not null default true,
  status text not null default 'active' check (status in ('active', 'suspended', 'closed')),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

-- 🆕 one row per shop: operational settings code relies on
create table merchant_settings (
  merchant_id uuid primary key references merchants (id) on delete cascade,
  closing_time time not null default '21:00',        -- business day cut-off
  payment_hold_minutes integer not null default 15,
  low_stock_threshold_pct integer not null default 20,
  default_lead_time_days integer not null default 0,
  quiet_hours jsonb not null default '{}',            -- {"from": "22:00", "to": "07:00"}
  alerts jsonb not null default '{}',                 -- morning reminder time, channels
  updated_at timestamptz not null default now()
);

-- 🆕 shops, home kitchens, warehouses; stock and pickup are per location
create table locations (
  merchant_id uuid not null references merchants (id) on delete cascade,
  id uuid not null default gen_random_uuid(),
  name text not null,
  kind text not null default 'shop' check (kind in ('shop', 'home', 'warehouse')),
  address jsonb not null default '{}',                -- line1, area, city, state, pincode
  lat numeric(9,6), lng numeric(9,6),
  pickup_enabled boolean not null default true,
  is_default boolean not null default false,
  created_at timestamptz not null default now(),
  primary key (merchant_id, id)
);
create unique index locations_one_default on locations (merchant_id) where is_default;

-- 🆕 holiday mode and planned closures
create table merchant_closures (
  merchant_id uuid not null references merchants (id) on delete cascade,
  id uuid not null default gen_random_uuid(),
  starts_on date not null,
  ends_on date not null check (ends_on >= starts_on),
  reason text,
  accept_preorders boolean not null default false,
  primary key (merchant_id, id)
);

-- 🆕 per-shop numbering: every shop's orders start at #1001, invoices at 1
create table merchant_counters (
  merchant_id uuid not null references merchants (id) on delete cascade,
  kind text not null check (kind in ('order', 'invoice', 'return')),
  next_value bigint not null,
  primary key (merchant_id, kind)
);
```

### 3.4 Catalog

```sql
-- 🆕 global: what each kind of business starts with (editable by the shop afterwards)
create table category_templates (
  code text primary key,                       -- 'clothing', 'bakery', 'jewellery', ...
  name text not null,
  default_stock_mode text not null,
  default_options jsonb not null default '[]', -- [{"name": "Size", "values": ["S","M","L"], "affects_stock": true}]
  attribute_schema jsonb not null default '{}',-- JSON Schema: material, allergens, care, ...
  personalization jsonb not null default '[]', -- suggested questions (cake message, ...)
  agent_guidance text                          -- extra rules for the agent ("always ask the size")
);

-- 🆕 the shop's own groupings: "Kurtis", "Birthday cakes"
create table collections (
  merchant_id uuid not null references merchants (id) on delete cascade,
  id uuid not null default gen_random_uuid(),
  parent_id uuid,
  name text not null,
  position integer not null default 0,
  primary key (merchant_id, id),
  foreign key (merchant_id, parent_id) references collections (merchant_id, id)
);

-- 🟢 extended
create table products (
  merchant_id uuid not null references merchants (id) on delete cascade,
  id uuid not null default gen_random_uuid(),
  collection_id uuid,
  template_code text references category_templates (code),
  name text not null check (length(trim(name)) > 0),
  description text,
  kind text not null default 'standard' check (kind in ('standard', 'bundle')),
  stock_mode text not null default 'inventory'
    check (stock_mode in ('daily', 'inventory', 'made_to_order', 'unlimited')),
  shelf_life_days integer,                     -- e.g. 1 for fresh cream cakes, 3-5 for cookies, null for non-perishable
  track_units boolean not null default false,  -- serial numbers / IMEI per unit
  track_batches boolean not null default false,-- batches with expiry dates
  pricing_mode text not null default 'fixed'
    check (pricing_mode in ('fixed', 'per_unit', 'tiered', 'formula', 'on_request')),
  unit text not null default 'piece',          -- piece, kg, g, metre, litre, set
  quantity_step numeric(12,3) not null default 1,   -- 0.25 for "kg in quarters"
  min_quantity numeric(12,3) not null default 1,
  max_quantity numeric(12,3),
  lead_time_days integer,                      -- null = shop default
  attributes jsonb not null default '{}',      -- material, allergens, care, dimensions, ...
  requires_shipping boolean not null default true,
  shipping_weight_g integer,
  shipping_dimensions_cm jsonb,                -- {"l": 30, "w": 20, "h": 5}
  hsn_code text, gst_rate numeric(5,2),        -- GST
  status text not null default 'active' check (status in ('draft', 'active', 'archived')),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  primary key (merchant_id, id),
  foreign key (merchant_id, collection_id) references collections (merchant_id, id)
);
create unique index products_name_idx on products (merchant_id, lower(name)) where status <> 'archived';
create index products_attributes_idx on products using gin (attributes jsonb_path_ops);

-- 🆕 option dimensions: Size, Colour, Flavour, Weight, Phone model, Gift wrap
create table product_options (
  merchant_id uuid not null,
  id uuid not null default gen_random_uuid(),
  product_id uuid not null,
  name text not null,
  affects_stock boolean not null default true, -- true: each value combination is a variant
  required boolean not null default true,
  position integer not null default 0,
  primary key (merchant_id, id),
  unique (merchant_id, product_id, name),
  foreign key (merchant_id, product_id) references products (merchant_id, id) on delete cascade
);

create table product_option_values (
  merchant_id uuid not null,
  id uuid not null default gen_random_uuid(),
  option_id uuid not null,
  value text not null,                         -- "M", "Red", "Eggless", "iPhone 15"
  price_delta_minor integer not null default 0,-- add-on price for order-time choices (+₹50)
  swatch text,                                 -- colour hex or image key
  position integer not null default 0,
  primary key (merchant_id, id),
  unique (merchant_id, option_id, value),
  foreign key (merchant_id, option_id) references product_options (merchant_id, id) on delete cascade
);

-- 🔁 extended: the sellable unit
create table product_variants (
  merchant_id uuid not null,
  id uuid not null default gen_random_uuid(),
  product_id uuid not null,
  option_values jsonb not null default '{}',   -- {"Size": "M", "Colour": "Red"}; {} = default variant
  option_key text not null default '',         -- normalised "colour=red|size=m", unique per product
  sku text,
  barcode text,
  price_minor integer,                         -- per piece, or per unit for per_unit pricing; null for on_request
  compare_at_price_minor integer,              -- MRP / strike-through price
  cost_minor integer,                          -- for profit insights
  currency char(3) not null default 'INR',
  stock_mode text check (stock_mode is null or stock_mode in ('daily', 'inventory', 'made_to_order', 'unlimited')),
  shelf_life_days integer,                     -- variant override (e.g. eggless bake vs regular)
  attributes jsonb not null default '{}',      -- variant-specific: weight_g of this ring, shade code
  status text not null default 'active' check (status in ('active', 'archived')),
  position integer not null default 0,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  primary key (merchant_id, id),
  unique (merchant_id, product_id, option_key),
  foreign key (merchant_id, product_id) references products (merchant_id, id) on delete cascade,
  check (price_minor is null or price_minor >= 0)
);
create unique index product_variants_sku_idx on product_variants (merchant_id, sku) where sku is not null;
create index product_variants_options_idx on product_variants using gin (option_values jsonb_path_ops);

-- 🆕 quantity tiers: wedding cards 100+ at ₹18, 500+ at ₹15
create table variant_price_tiers (
  merchant_id uuid not null,
  variant_id uuid not null,
  min_quantity numeric(12,3) not null,
  unit_price_minor integer not null check (unit_price_minor >= 0),
  primary key (merchant_id, variant_id, min_quantity),
  foreign key (merchant_id, variant_id) references product_variants (merchant_id, id) on delete cascade
);

-- 🆕 daily rates for formula pricing: gold 22k per gram, silver per gram
create table rate_cards (
  merchant_id uuid not null references merchants (id) on delete cascade,

  effective_on date not null,
  rate_minor integer not null,                 -- per unit below
  unit text not null default 'g',
  primary key (merchant_id, code, effective_on)
);

-- {"pricing": {"rate": "gold_22k", "weight_attr": "weight_g", "making_pct": 12, "fixed_minor": 50000}}
-- The price is computed in code at quote time and stored as a snapshot on the order line.

-- 🆕 questions the customer must answer: cake message, name to engrave, photo to print
create table personalization_fields (
  merchant_id uuid not null,
  id uuid not null default gen_random_uuid(),
  product_id uuid not null,
  key text not null,                           -- 'cake_message'
  label text not null,                         -- "Message on the cake"
  type text not null check (type in ('text', 'long_text', 'number', 'date', 'photo', 'choice')),
  required boolean not null default false,
  max_length integer,
  choices jsonb,                               -- for type = choice
  price_delta_minor integer not null default 0,
  position integer not null default 0,
  primary key (merchant_id, id),
  unique (merchant_id, product_id, key),
  foreign key (merchant_id, product_id) references products (merchant_id, id) on delete cascade
);

-- 🆕 hampers and kits: holding a bundle holds its parts
create table bundle_components (
  merchant_id uuid not null,
  bundle_variant_id uuid not null,
  component_variant_id uuid not null,
  quantity numeric(12,3) not null check (quantity > 0),
  primary key (merchant_id, bundle_variant_id, component_variant_id),
  foreign key (merchant_id, bundle_variant_id) references product_variants (merchant_id, id) on delete cascade,
  foreign key (merchant_id, component_variant_id) references product_variants (merchant_id, id)
);

-- 🆕 names customers actually use, learned from merchant corrections
create table product_aliases (
  merchant_id uuid not null,
  id uuid not null default gen_random_uuid(),
  product_id uuid not null,
  variant_id uuid,
  alias text not null,                         -- stored lower-case, trimmed
  source text not null default 'merchant' check (source in ('merchant', 'learned')),
  primary key (merchant_id, id),
  unique (merchant_id, alias, product_id),
  foreign key (merchant_id, product_id) references products (merchant_id, id) on delete cascade
);
create index product_aliases_trgm on product_aliases using gin (alias gin_trgm_ops);

-- 🆕 every image, video, voice note and upload (files live in object storage)
create table media_assets (
  merchant_id uuid not null references merchants (id) on delete cascade,
  id uuid not null default gen_random_uuid(),
  storage_key text not null,                   -- bucket path; never the file itself
  mime_type text not null,
  bytes bigint, width integer, height integer, duration_ms integer,
  source text not null check (source in ('merchant_upload', 'instagram', 'customer', 'generated')),
  fingerprint bigint,                          -- perceptual hash, for "is this our story/product?"
  created_at timestamptz not null default now(),
  primary key (merchant_id, id)
);
create index media_assets_fingerprint_idx on media_assets (merchant_id, fingerprint) where fingerprint is not null;

create table product_media (
  merchant_id uuid not null,
  product_id uuid not null,
  media_id uuid not null,
  variant_id uuid,                             -- colour-specific photos
  position integer not null default 0,
  alt_text text,
  primary key (merchant_id, product_id, media_id),
  foreign key (merchant_id, product_id) references products (merchant_id, id) on delete cascade,

-- 🆕 search document per product, refreshed by a job when the product changes
create table product_search (
  merchant_id uuid not null,
  product_id uuid not null,
  document tsvector not null,                  -- name, description, option values, attributes, aliases
  text_blob text not null,                     -- the same, plain, for fuzzy (trigram) matching

  embedding_model text,
  updated_at timestamptz not null default now(),
  primary key (merchant_id, product_id),
  foreign key (merchant_id, product_id) references products (merchant_id, id) on delete cascade
);
create index product_search_fts on product_search using gin (document);
create index product_search_trgm on product_search using gin (text_blob gin_trgm_ops);
create index product_search_vec on product_search using hnsw (embedding vector_cosine_ops);
```

### 3.5 Stock and capacity

```sql
-- 🔁 replaces daily_stock: current balances for daily and inventory products
create table stock_levels (
  merchant_id uuid not null,
  variant_id uuid not null,
  location_id uuid not null,
  stock_date date,                             -- the day for 'daily' products; null for 'inventory'
  on_hand numeric(12,3) not null default 0 check (on_hand >= 0),
  held numeric(12,3) not null default 0 check (held >= 0),
  available numeric(12,3) generated always as (on_hand - held) stored,
  updated_at timestamptz not null default now(),
  unique nulls not distinct (merchant_id, variant_id, location_id, stock_date),
  check (on_hand - held >= 0),                 -- never promise more than exists
  foreign key (merchant_id, variant_id) references product_variants (merchant_id, id),
  foreign key (merchant_id, location_id) references locations (merchant_id, id)
);
-- hold:    update ... set held = held + q            where ... and on_hand - held >= q
-- sell:    update ... set held = held - q, on_hand = on_hand - q
-- release: update ... set held = held - q
-- restock: update ... set on_hand = on_hand + q

-- 🆕 every hold, per order line (auditable, expires, works for bundles and serial units)
create table stock_reservations (
  merchant_id uuid not null,
  id uuid not null default gen_random_uuid(),
  order_id uuid not null,
  order_item_id uuid not null,
  variant_id uuid not null,
  location_id uuid not null,
  stock_date date,
  quantity numeric(12,3) not null check (quantity > 0),
  status text not null default 'held' check (status in ('held', 'converted', 'released')),
  expires_at timestamptz,
  created_at timestamptz not null default now(),
  primary key (merchant_id, id)
);
create index stock_reservations_expiry on stock_reservations (expires_at) where status = 'held';

-- 🆕 the history of every stock change (partitioned monthly): reporting reads this
create table stock_movements (
  merchant_id uuid not null,
  id uuid not null default gen_random_uuid(),
  variant_id uuid not null,
  location_id uuid not null,
  stock_date date,
  kind text not null check (kind in ('opening', 'restock', 'sale', 'counter_sale', 'return',
                                     'waste', 'adjustment', 'transfer_in', 'transfer_out')),
  quantity numeric(12,3) not null,             -- signed: + adds stock, - removes it
  order_id uuid,
  note text,
  actor text not null check (actor in ('merchant', 'agent', 'system')),
  created_at timestamptz not null default now(),
  primary key (merchant_id, id, created_at)
) partition by range (created_at);

-- 🆕 per-unit tracking: phones (IMEI), watches (serial), one-of-a-kind pieces if wanted
create table inventory_units (
  merchant_id uuid not null,
  id uuid not null default gen_random_uuid(),
  variant_id uuid not null,
  location_id uuid not null,
  serial_number text not null,
  status text not null default 'in_stock'
    check (status in ('in_stock', 'reserved', 'sold', 'returned', 'defective')),
  order_item_id uuid,
  received_at timestamptz not null default now(),
  sold_at timestamptz,
  primary key (merchant_id, id),
  unique (merchant_id, serial_number),
  foreign key (merchant_id, variant_id) references product_variants (merchant_id, id)
);

-- 🆕 batches with expiry (cosmetics, packaged food): sell the oldest first (phase 3)
create table inventory_batches (
  merchant_id uuid not null,
  id uuid not null default gen_random_uuid(),
  variant_id uuid not null,
  location_id uuid not null,
  batch_code text not null,
  expires_on date,
  on_hand numeric(12,3) not null default 0 check (on_hand >= 0),
  primary key (merchant_id, id),
  unique (merchant_id, variant_id, location_id, batch_code),
  foreign key (merchant_id, variant_id) references product_variants (merchant_id, id)
);

-- 🆕 made to order and delivery slots: "8 custom cakes a day", "tiffin slot 12–1 pm: 40 meals"
create table capacity_slots (
  merchant_id uuid not null,
  id uuid not null default gen_random_uuid(),
  product_id uuid,                             -- null = shop-wide (e.g. delivery slots)
  slot_date date not null,
  starts_at time, ends_at time,                -- null = the whole day
  capacity numeric(12,3) not null check (capacity >= 0),
  booked numeric(12,3) not null default 0 check (booked >= 0),
  primary key (merchant_id, id),
  unique nulls not distinct (merchant_id, product_id, slot_date, starts_at),
  check (booked <= capacity)                   -- booking is the same one-update pattern as stock
);
-- capacity_rules (weekday templates the slots are generated from) is a small JSONB in
-- merchant_settings or products.attributes; a nightly job creates the coming weeks' slots.
```

## 4. Every scenario, and how the schema handles it

### By kind of business

| Business | Product setup | Stock | Pricing | Ordering |
|---|---|---|---|---|
| **Clothing, footwear, kidswear** | Options Size, Colour (stock); size chart in `attributes`; colour photos in `product_media.variant_id` | `inventory` per variant | `fixed`; MRP in `compare_at_price_minor` | `returns` for exchanges |
| **Sarees, art, vintage (one-offs)** | One product per piece, one default variant | `inventory` with quantity 1; sold out = gone | `fixed` | Archived when sold; bulk-created from posts via `channel_media` |
| **Gold / silver jewellery** | `attributes.weight_g`, purity | `inventory`, or `track_units` for hallmarked pieces | `formula` with `rate_cards` (rate × weight + making charge) | Price snapshot in `price_breakdown` |
| **Imitation jewellery, bags, watches** | Options Colour/Style | `inventory`; watches can use `track_units` | `fixed` | — |
| **Bakery** | Options Flavour, Weight (stock); Eggless as an order-time choice (+₹50) | `daily` for cookies and brownies; `made_to_order` + `capacity_slots` for cakes | `fixed` per variant | `personalization_fields`: message, name; lead time; deposits |
| **Homemade food, tiffin** | Daily menu items | `daily`; delivery slots in `capacity_slots` | `fixed` | `subscriptions` for weekly plans; `scheduled_window` |
| **Chocolates, sweets** | Weight options (250 g / 500 g), or `per_unit` by kg | `daily` or `inventory` | `fixed` or `per_unit` | Hampers via `bundle_components` |
| **Gift hampers** | `kind = bundle` | Holding a hamper holds its parts | `fixed` | Gift fields on the order |
| **Flowers** | Options Size; arrangement choices | `made_to_order` with daily capacity | `fixed` | `scheduled_date` and window are critical |
| **Custom gifts, printed mugs, wedding cards** | Personalization: name, photo upload | `made_to_order` or `unlimited` | `tiered` (100+ cheaper) | `order_proofs` before printing; deposit |
| **Mobile accessories / print-on-demand** | Design as stock option; **Phone model as an order-time choice** | `unlimited` or `made_to_order` | `fixed` plus `price_delta_minor` | 50 designs × 40 phones without 2,000 variant rows |
| **Phones, electronics resellers** | Model, storage as options | `track_units` with IMEI in `inventory_units` | `fixed` | The unit's serial is recorded on sale; returns |
| **Beauty, cosmetics** | Shade as option; ingredients in `attributes` | `inventory`; `track_batches` for expiry | `fixed` | — |
| **Candles, fragrances, natural products** | Scent × size | `inventory` | `fixed` | — |
| **Plants** | Size; care info in `attributes` | `inventory` | `fixed` | Local delivery zones |
| **Fabric, loose spices** | `unit = metre / kg`, `quantity_step` | `inventory` in decimals | `per_unit` | Quantity 2.5 m |
| **Tea, coffee, healthy food** | Grind × weight | `inventory` | `fixed` | `subscriptions` for refills |
| **Pickles, packaged food (shipped)** | Weight options; `shipping_weight_g` | `inventory`; batches | `fixed` | `courier` fulfilment, tracking |
| **Books, stationery** | ISBN in `barcode` | `inventory` | `fixed` | — |
| **Pet products** | Size for collars; ingredients for treats | `inventory` | `fixed` | — |
| **Services later** (mehendi, makeup, tailoring) | `made_to_order`, with `capacity_slots` as appointments | — | `fixed` / `on_request` | Bookings reuse slots |
| **Price on request** | `pricing_mode = on_request` | any | none shown | The agent escalates for a quote |

### Edge cases

| Scenario | Handled by |
|---|---|
| Two customers want the last item / last cake slot / last serial-numbered phone | One conditional update on `stock_levels`, `capacity_slots` or `inventory_units` |
| Hold expires unpaid | `stock_reservations.expires_at` → job releases → `stock_movements` not needed (holds aren't movements) |
| Paid after the hold expired | Order snapshot plus re-check; shortfall → escalation (already built) |
| Shop has a counter and a warehouse | `locations`; stock per location; transfers in `stock_movements` |
| Product renamed or deleted after orders exist | Products are archived, never deleted; orders keep snapshots |
| Price changed mid-chat | The quote is computed at quote time; the order keeps its snapshot |
| Customer orders on Instagram, later on WhatsApp | One customer, two rows in `customer_identities` |
| Gift order to someone else | `orders.is_gift` + `gift` jsonb + recipient address |
| Advance now, balance later | `payments.kind` deposit/balance; `orders.payment_status = partially_paid` |
| Partial refund, partial return | `refunds`, `returns.items`, `payment_status = partially_refunded` |
| Ship part of an order now | `fulfilments.items` |
| Merchant on holiday | `merchant_closures`; the agent declines or takes pre-orders |
| GST-registered shop | `merchants.gstin`, `products.hsn_code / gst_rate`, `invoices` |
| A customer asks to be forgotten (DPDP) | `data_requests`; partitioned history makes retention cheap |
| Staff handle chats | `merchant_members.role`, `conversations.assigned_user_id` |
| "Do you have red kurti size M under ₹1000?" | `product_search` + filters on `option_values` / `price_minor` (section 6) |
| "Is this in stock?" with a story screenshot | `media_assets.fingerprint` → `channel_media_products` |
| Missed sales for insights | `demand_events` |

## 5. Scale

**A deliberately large target:** 100,000 shops, 500 products and 2,000 variants on average, 200 DMs per shop per day.

| Table | Size | Approach |
|---|---|---|
| products / variants | ~50 M / ~200 M rows | Every query is per shop (`merchant_id` first in every index): fast at any total size |
| product_search | ~50 M rows | GIN + HNSW indexes, per shop filtering |
| stock_levels | ~200 M (inventory) + daily rows | Old daily rows archived after the day closes (history is in `stock_movements`) |
| **messages** | **~20 M/day, ~7 B/year** | **Monthly partitions**; retention (e.g. 12 months) by dropping partitions; old months to cold storage |
| stock_movements, order_events, ai_usage | tens of millions/day combined | Monthly partitions |
| orders / order_items | ~2 M / ~5 M per day | Monthly partitions if needed after year 1 |

**The path, step by step (no redesign at any step):**
1. **One Postgres server** (managed), with the indexes and partitions above. Comfortable for the first several thousand shops.
2. **Read replicas** for insights, exports and search-heavy reads.
3. **Citus**, splitting shop tables across servers by `merchant_id`. The composite keys (decision 2) are what make this a configuration step, not a migration. Global tables (users, templates, plans) become Citus "reference tables".
4. Only if needed much later: a dedicated search engine (OpenSearch) fed from `product_search`, and a dedicated job queue.

**Indexing rules:** every shop table's indexes start with `merchant_id`; JSONB columns that are filtered get `jsonb_path_ops` GIN indexes; fuzzy search uses `pg_trgm`; vectors use HNSW. Extensions needed: `pg_trgm`, `vector` (pgvector), plus the built-in `gen_random_uuid()`.

## 6. What the AI agent reads

The agent must **never** get a whole catalog in its prompt. A 20-item bakery fits; a 5,000-item reseller doesn't, and the cost would break the low-cost rule.

| Shop size | What goes in the prompt |
|---|---|
| Small (≤ ~40 sellable variants available today) | Today's stock list, as now (cheap, cached) |
| Larger | A short summary ("We sell kurtis, sarees, dupattas; sizes S–XXL") plus a **`search_catalog` tool** |

`search_catalog(query, filters)` runs in Postgres: full-text and fuzzy match on `product_search`, meaning search on `embedding` (handles Tamil-English phrasing), filters on `option_values`, price and availability. It returns the top 5–10 variants with price and stock. Quotes and orders then work exactly as today (by variant), so the order code doesn't change.

## 7. Moving from the current schema

Today's tables: merchants, channel_connections, customers, conversations, messages, products, product_variants, daily_stock, shop_profiles, shop_onboarding, escalations, ai_usage, webhook_events, orders, order_items, order_events, payments, users, user_identities, merchant_members, sessions, login_codes.

| Step | Change | Code impact |
|---|---|---|
| 1 | Composite keys `(merchant_id, id)` and composite foreign keys on shop tables | Models and lookups pass `merchant_id` (most queries already filter by it) |
| 2 | Catalog v2: options, variant `option_values`, attributes, stock modes, pricing modes, personalization, media, aliases | catalog module; agent prompt; quote/place code reads `option_values` |
| 3 | `daily_stock` → `stock_levels` + `stock_reservations` + `stock_movements`; `locations` (one default per shop) | inventory module (same conditional-update pattern) |
| 4 | Orders: three statuses, per-shop numbers, snapshots, gift and schedule fields | orders module and API |
| 5 | Search + `search_catalog` tool | agent module |
| 6 | Partition the big history tables | migrations only |
| 7+ | Capacity slots, bundles, tiers, formula pricing, subscriptions, returns, proofs, fulfilments, invoices, billing | One feature at a time, each with its own migration and tests |

There's no production data yet, so steps 1–4 can be done as a clean rebuild of the dev database rather than data migrations. That's the cheapest moment to make them.

## 8. Open decisions

| # | Question | Proposed answer |
|---|---|---|
| 1 | Composite `(merchant_id, id)` keys now, or plain `id` keys and convert at sharding time? | **Now.** Converting billions of rows later is the expensive path, and the database-enforced shop isolation is worth having today. |
| 2 | Embedding model and dimension for `product_search` | Decide with the model bake-off (multilingual, cheap); `vector(1024)` is a placeholder |
| 3 | Object storage: Firebase Storage or S3-compatible | Firebase Storage (already planned for the app) |
| 4 | Database host | Render Postgres or Neon (both support `pgvector` and `pg_trgm`; Citus later via Azure Cosmos DB for PostgreSQL or self-managed) |
| 5 | Message retention period | 12 months of full messages, then summaries only (confirm against DPDP guidance) |
